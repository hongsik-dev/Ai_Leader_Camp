# CatchPro 사용설명서

## 1. 앱 목적

CatchPro는 인성 앱의 오더 상세 화면을 읽어 다음 목적에 맞게 보조하는 안드로이드 앱입니다.

1. `도착지`, `상차지까지 거리`, `요금` 3가지 조건이 맞는 오더를 자동으로 확정
2. 메인 오더를 확정한 뒤, 그 오더의 목적지와 비슷한 추가 오더를 이어서 확정
3. 비슷한 목적지의 다수 오더를 빠른 시간 안에 배송

중요:
- 현재 1차/2차 자동확정은 모두 `오더 상세 화면`에서만 동작합니다.
- 인성 리스트에서 오더를 `사용자가 직접 눌러 상세 화면으로 들어간 뒤` CatchPro가 조건을 판정합니다.
- 조건이 맞으면 `확정` 버튼을 자동으로 누르거나, `수동 확인`이 켜져 있으면 확인창을 띄웁니다.

---

## 2. 화면 역할

### 대시보드
- 앱의 현재 목적과 자동확정 기준을 한 번에 보는 메인 화면입니다.
- 현재 저장된 `메인 오더 목적지`, `도착지 조건`, `상차 거리`, `최소 요금`, `추가 목적지 반경`을 요약해서 보여줍니다.
- `오더 조건`, `목적지` 화면으로 빠르게 이동할 수 있습니다.

### 오더 조건
- 실제 자동확정 규칙을 설정하는 핵심 화면입니다.
- 여기서 아래 항목을 관리합니다.
  - 도착지 조건
  - 상차지 거리 조건
  - 최소 요금 조건
  - 메인 오더 목적지 반경
  - 자동확정 사용 여부

### 목적지
- 자주 가는 배송 축, 대표 주소, 권역을 저장하는 화면입니다.
- 예:
  - 강남권 배송
  - 인천 서구 축
  - 분당 복귀축
- 오더 조건에서 쓰는 도착지 기준과 목적지 데이터를 같은 흐름으로 정리하는 용도입니다.

### 이력
- 확정, 자동확정, 자동취소, 수행중 목적지 연동 등의 이벤트 로그를 보는 화면입니다.

### 설정
- 시스템 설정만 다루는 화면입니다.
- 예:
  - 접근성 켜기
  - 관찰 패키지 필터
  - 안전 모드
  - 알림
  - 로그 보관 기간

## 3. 처음 사용할 때

### 3-1. 앱 설치
- APK 위치:
  - `app/build/outputs/apk/debug/app-debug.apk`
- 휴대폰에 설치한 뒤 실행합니다.

### 3-2. 접근성 켜기
1. 앱에서 `설정` 화면으로 이동
2. `접근성 설정` 버튼 누르기
3. `CatchPro Observation` 켜기

안드로이드 13 이상에서 막히면:
- `설정 > 앱 > CatchPro > 점 3개 > 제한된 설정 허용`

### 3-3. 관찰 패키지 필터
- `설정 > 관찰 패키지 필터`
- 인성 앱 패키지명을 넣습니다.
- 현재 기준:
  - `insung.split.quick`

## 4. 핵심 사용 흐름

### 4-1. 메인 오더 목적지 저장

메인 오더를 수행 중일 때, 그 목적지를 추가 오더의 기준점으로 써야 합니다.

방법:
1. 인성 앱에서 `메인 오더 상세 화면`을 엽니다.
2. 화면 오른쪽에 뜨는 `수행중 저장` 버튼을 누릅니다.
3. 현재 화면의 도착지가 CatchPro의 `메인 오더 목적지`로 저장됩니다.

특징:
- 상태문구를 저희가 정확히 몰라도 됩니다.
- 현재 보고 있는 상세 화면의 도착지를 기준점으로 직접 저장하는 방식입니다.

---

### 4-2. 자동확정 조건 설정

`오더 조건` 화면에서 아래 4가지를 설정합니다.

1. 도착지 조건
- 예:
  - `강남구`
  - `역삼동`
  - `서울 강남구`
- 여러 개는 줄바꿈 또는 쉼표로 입력할 수 있습니다.

2. 상차지 거리 조건
- 현재 위치에서 상차지까지 허용할 최대 거리
- 예:
  - `1`
  - `2.5`

3. 최소 요금 조건
- 예:
  - `15000`
  - `30000`

4. 메인 오더 목적지 반경
- 현재 저장된 메인 오더 목적지 기준으로
- 추가 오더의 도착지가 몇 km 안에 있어야 하는지 설정
- 예:
  - `3`

자동확정은 `입력한 조건을 모두 만족`해야 동작합니다.

즉 예를 들어:
- 도착지 = 강남구
- 상차지 거리 <= 1km
- 요금 >= 20000원
- 메인 오더 목적지 반경 <= 3km

이면 이 4가지를 모두 만족하는 상세 오더만 자동확정합니다.

---

### 4-3. 전국 지역에서 선택

`오더 조건`과 `목적지` 양쪽 화면에서 `전국 지역 선택` 기능을 사용할 수 있습니다.

흐름:
1. 시/도 선택
2. 시/군/구 선택
3. 확인

예:
- 서울 선택
- 강남구 선택

이렇게 저장하면 `강남구 역삼동`, `강남구 논현동`, `강남구 삼성동` 같은 주소도 같은 권역으로 매칭됩니다.

---

## 5. 실제 자동확정 동작 방식

현재 자동확정은 아래 순서로 동작합니다.

1. 사용자가 인성 목록에서 오더를 눌러 `상세 화면` 진입
2. CatchPro가 상세 화면의 내용을 읽음
3. 도착지, 상차 거리, 요금, 메인 오더 목적지 반경 조건 비교
4. 조건이 모두 맞으면 `확정` 버튼 자동 클릭

중요:
- 목록 화면을 OCR로 자동 클릭하는 방식은 사용하지 않습니다.
- `상세 화면`에서만 자동확정합니다.

---

## 6. 자동취소 대응

자동으로 잡은 오더를 사용자가 나중에 `취소`하면, CatchPro는 그걸 별도 이벤트로 기록합니다.

현재 동작:
- 자동확정한 오더에서 `취소` 버튼 클릭이 감지되면
- `auto-cancelled` 로그를 남김
- 같은 오더를 `90초 동안 다시 자동확정하지 않음`

이 기능은 같은 오더를 바로 다시 잡는 문제를 줄이기 위한 보호 로직입니다.

---

## 7. 이력에서 볼 수 있는 상태

이력에는 다음과 같은 이벤트가 남을 수 있습니다.

- `confirmed`
- `auto-confirmed`
- `active-drive-synced`
- `active-drive-manual-sync`
- `auto-cancelled`
- `skipped`

설명:
- `auto-confirmed`: 조건이 맞아 자동확정됨
- `active-drive-manual-sync`: `수행중 저장` 버튼으로 메인 오더 목적지 저장
- `auto-cancelled`: 자동확정된 오더가 취소됨

---

## 8. 캡처 로그 사용법

인성 화면 구조를 점검할 때는 `설정 > 캡처 로그`를 사용합니다.

할 수 있는 일:
- 최근 인성 화면 텍스트 구조 확인
- 파싱 결과 확인
- 로그 파일 저장

로그 파일에 포함되는 값:
- package
- event
- summary
- nodeCount
- parsed.status
- parsed.screenMode
- parsed.origin
- parsed.destination
- parsed.confirmAction
- parsed.cancelAction
- raw hierarchy

## 9. 추천 사용 순서

### 빠른 시작
1. 앱 설치
2. 접근성 켜기
3. 패키지 필터를 `insung.split.quick`로 저장
4. `오더 조건`에서 자동확정 규칙 입력
5. 인성 메인 오더 상세 화면에서 `수행중 저장`
6. 추가 오더 상세 화면 진입
7. 조건이 맞으면 자동확정

### 실사용 예시
예를 들어
- 메인 오더 목적지: `강남구 역삼동 123-1`
- 도착지 조건: `강남구`, `역삼동`
- 상차지 거리: `1km`
- 최소 요금: `20000원`
- 메인 오더 목적지 반경: `3km`

이면
- 현재 위치에서 상차지가 1km 안
- 도착지가 강남구/역삼동 권역
- 요금이 2만원 이상
- 메인 오더 목적지에서 3km 안

인 추가 오더만 자동확정됩니다.

## 10. 문제 해결

### 수행중 저장 버튼이 안 보일 때
- 인성 `상세 화면`인지 확인
- 도착지 텍스트가 실제로 보이는 화면인지 확인
- 접근성이 켜져 있는지 확인
- 패키지 필터가 `insung.split.quick`로 되어 있는지 확인

### 자동확정이 안 될 때
- `오더 조건`에서 자동확정 스위치가 켜져 있는지 확인
- 도착지 조건, 상차 거리, 최소 요금 중 빈 값이 아닌 조건이 제대로 들어갔는지 확인
- 메인 오더 목적지 반경을 쓰는 경우 `수행중 저장`을 먼저 했는지 확인

### 캡처 로그에 다른 앱이 섞일 때
- `설정 > 관찰 패키지 필터`를 `insung.split.quick`로 고정

### 취소 후 같은 오더가 바로 다시 잡힐 때
- 현재는 90초 재확정 방지 로직이 들어가 있습니다
- 그래도 반복되면 해당 로그 파일을 저장해서 확인이 필요합니다

---

## 11. 현재 구조의 한계

- 자동확정은 `목록 화면`이 아니라 `상세 화면` 기준입니다.
- 메인 오더 목적지는 현재 `수행중 저장` 버튼으로 저장하는 방식이 가장 안정적입니다.
- 인성 앱의 실제 상태문구가 더 많이 확보되면, 추후 자동 동기화 정확도를 더 높일 수 있습니다.
