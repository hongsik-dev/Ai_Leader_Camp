# 2026-05-24 CatchPro 구독형 운영 구현 과제

## 목표

CatchPro 수익화는 공개 Play Store 앱과 폐쇄형 유료 APK를 분리해서 운영한다.

- `CatchPro Navi Free/Pro`: Play Store 공개 가능성을 우선 검토하는 지도/네비 앱.
- `CatchPro Pro 구독`: 홈페이지 신청, 상담, 결제, 라이선스 인증 후 인성 CatchPro Pro와 CatchPro Navi Pro를 함께 제공하는 통합 구독.

핵심 원칙은 인성 CatchPro의 오더 확정 속도를 건드리지 않는 것이다. 결제, 라이선스, 다운로드, 홈페이지 기능은 앱의 오더리스트 진입/확정 루프와 분리해서 구현한다.

## 운영 구조

### 1. 공개入口: CatchPro Navi

Play Store에는 먼저 CatchPro Navi를 공개한다.

- 지도 표시
- 주소 1~6 관리
- 방문순서/예상시간 계산
- 네이버/TMAP 네비 연결
- 인성 CatchPro Pro 문의 안내

Navi 앱 안에서는 외부 결제를 강하게 유도하지 않는다. 문구는 다음 수준으로 제한한다.

- "인성 CatchPro Pro는 별도 상담형 서비스입니다."
- "설치 가능 여부 확인"
- "문의하기"

### 2. 유료 핵심 상품: CatchPro Pro 구독

CatchPro Pro 구독은 Play Store 공개 배포가 아니라 신청형 APK로 운영한다.
하나의 구독으로 인성 CatchPro Pro와 CatchPro Navi Pro 사용 권한을 함께 관리한다.

- 홈페이지에서 신청
- 카카오톡/문자로 상담
- 실제 기사 여부와 사용 환경 확인
- 결제 확인
- 개인별 APK 다운로드 링크 제공
- 앱에서 AWS 라이선스 서버 확인

## 내일 구현 범위

내일은 자동결제까지 바로 붙이지 않고, 1차 MVP를 만든다.

### 1차 MVP

1. 홈페이지 신청 페이지
2. 신청 데이터 저장
3. 관리자용 라이선스 목록
4. AWS 라이선스 확인 API
5. 인성 CatchPro Pro 앱의 라이선스 체크
6. 개인별 APK 다운로드 링크 설계

자동결제는 2차 작업으로 미룬다. 먼저 결제 여부와 앱 권한을 통제할 수 있어야 한다.

## 역할 분리

### 사용자가 결정해야 하는 일

- 공식 서비스명, 도메인, 연락 채널을 확정한다.
- 월 구독 가격, 체험 기간, 환불 기준을 정한다.
- 고객에게 노출할 약관, 개인정보 수집 문구, 책임 범위를 승인한다.
- 결제 방식 1차안을 고른다. 초기에는 계좌이체/토스 송금/결제링크 같은 수동 결제가 가장 빠르다.
- 실제 기사 여부 확인 방식과 신청 승인 기준을 정한다.
- Pro APK를 받을 고객의 이메일, 전화번호, 기기 변경 처리 규칙을 운영한다.
- 자동결제를 붙일 시점에 토스페이먼츠 또는 다른 PG 계약 정보를 제공한다.

### Codex가 구현할 수 있는 일

- 홈페이지/블로그에 붙일 신청 페이지 초안과 운영 문서를 만든다.
- AWS 서버에 라이선스 확인 API를 추가한다.
- 앱에 Pro 라이선스 확인, 캐시, 유예 정책을 구현한다.
- 오더 확정 루프에서는 네트워크를 호출하지 않고 로컬 권한 캐시만 읽도록 만든다.
- 설정 화면에 라이선스 상태, 이메일/전화번호 입력, 수동 확인 버튼을 추가한다.
- 신청자/라이선스 JSON 또는 SQLite 운영 파일 구조를 만든다.
- 개인별 다운로드 토큰 설계를 문서화하고, 다음 단계에서 자동 다운로드 API를 만들 수 있게 한다.
- 빌드와 기본 테스트를 실행하고 GitHub에 변경 내역을 남긴다.

### 이번 구현 순서

1. 계획서에 역할 분리와 운영 순서를 명시한다.
2. 앱에 Pro 라이선스 캐시와 서버 확인 클라이언트를 추가한다.
3. 설정 화면에서 라이선스 상태를 확인하고 갱신할 수 있게 한다.
4. AWS 서버에 `/api/license/check`와 `/api/license/app-version`을 추가한다.
5. 빌드/스모크 테스트 후 GitHub 브랜치에 반영한다.

### 2026-05-24 구현 반영

- 앱에 `LicenseRepository`를 추가해서 Pro 라이선스 상태를 로컬 캐시에 저장한다.
- Pro 기능 게이트는 오더 확정 루프에서 네트워크를 호출하지 않고 캐시만 읽는다.
- Pro 설정 화면에 이메일, 전화번호, 기기코드, 최근 확인 시각, 라이선스 확인 버튼을 추가했다.
- AWS 서버에는 `/api/license/check`, `/api/license/app-version`, 관리자 토큰이 필요한 `/api/license/register-device` 초안을 추가했다.
- 라이선스 저장소는 `/opt/catchpro-sync/licenses.json`으로 시작한다. 초기에는 관리자가 SSH로 고객을 등록하고, 결제 확인 후 `active` 또는 `trial` 상태로 바꾸는 방식이다.

### 과제 2. 라이선스 서버 API 만들기

AWS 서버에 라이선스 확인 API를 추가한다.

예상 엔드포인트:

```text
POST /api/license/check
POST /api/license/register-device
GET  /api/license/app-version
```

`/api/license/check` 요청 예시:

```json
{
  "edition": "insung-pro",
  "email": "driver@example.com",
  "phone": "01000000000",
  "deviceId": "android-secure-id",
  "appVersion": "0.1.11-insung-pro"
}
```

응답 예시:

```json
{
  "ok": true,
  "licenseStatus": "active",
  "expiresAt": "2026-06-24T23:59:59+09:00",
  "message": "구독 사용 가능"
}
```

만료 응답 예시:

```json
{
  "ok": false,
  "licenseStatus": "expired",
  "message": "구독 기간이 만료되었습니다."
}
```

### 과제 3. 라이선스 저장소 만들기

초기에는 복잡한 DB보다 SQLite 또는 JSON 관리 파일로 시작해도 된다.

권장 필드:

```text
id
name
email
phone
edition
device_id
status
started_at
expires_at
memo
created_at
updated_at
```

상태값:

- `trial`: 체험판
- `active`: 정상 구독
- `expired`: 만료
- `blocked`: 차단
- `device_change_pending`: 기기 변경 대기

### 과제 4. 인성 CatchPro Pro 앱 라이선스 체크

앱 시작 시 또는 Pro 기능 실행 전에 AWS에 라이선스를 확인한다.

적용 기준:

- 개인 운행판은 라이선스 체크 제외
- Free는 Pro 기능 없음
- Pro는 서버 라이선스가 `active` 또는 `trial`일 때만 자동확정 사용 가능

중요:

- 라이선스 체크는 오더 확정 루프에서 직접 실행하지 않는다.
- 앱 실행, 설정 진입, 운행 시작 전 단계에서만 확인한다.
- 네트워크 장애 시에는 짧은 유예 정책을 둔다.

유예 정책 초안:

- 마지막 정상 인증 후 24시간은 임시 허용
- 24시간 이상 인증 실패 시 Pro 기능 잠금
- 잠금 상태에서는 안내 문구 표시

### 과제 5. 개인별 다운로드 링크 설계

이메일 첨부 대신 개인별 링크를 사용한다.

예시:

```text
https://catchpro.kr/download/{token}
```

링크 정책:

- 24시간 만료
- 최대 3회 다운로드
- 토큰은 추측 불가능한 난수
- 다운로드 로그 저장

초기 MVP에서는 실제 파일 다운로드 자동화 전까지 관리자 수동 발송으로 시작할 수 있다.

### 과제 6. 관리자 운영 화면

초기에는 WP 관리자 페이지 또는 간단한 별도 HTML 페이지로 시작한다.

필요 기능:

- 신청자 목록
- 구독 상태 변경
- 만료일 수정
- 기기코드 확인
- 다운로드 링크 생성
- 메모 기록

## 결제 운영 단계

### 1단계: 수동 결제

초기 운영은 수동 결제로 시작한다.

- 계좌이체
- 카카오페이/토스 송금
- 토스페이먼츠 결제링크
- 스마트스토어 결제

관리자가 결제 확인 후 라이선스를 `active`로 변경한다.

### 2단계: 자동결제

사용자가 늘어나면 토스페이먼츠 자동결제를 붙인다.

구조:

1. 사용자가 결제수단 등록
2. 토스페이먼츠 빌링키 발급
3. AWS 서버가 빌링키 저장
4. 매월 서버 스케줄러가 자동결제 승인 API 호출
5. 성공 시 라이선스 연장
6. 실패 시 재시도 후 만료 처리

주의:

- 자동결제는 토스페이먼츠 추가 계약/심사가 필요할 수 있다.
- 카드 정보 원문은 저장하지 않는다.
- 빌링키와 결제 로그는 서버에서만 관리한다.

## 앱별 정책

### 인성 CatchPro Free

- 권한 확인과 Pro 체험 신청 중심
- 오더 조건 탭은 하단 내비게이션에서 제외
- 하단에는 `Pro 체험하기` 탭을 제공
- `Pro 체험하기`는 첫 달 무료체험, 월 9,900원 구독 전환, 상담 신청 링크를 안내
- 오더 조건 저장, 자동확정, 자동상세확정 없음
- 유료 전환 안내는 앱 내부에서 과하지 않게 표시

### 인성 CatchPro Pro

- 오더 조건 저장 제공
- 수동 상세 진입 후 조건이 맞으면 자동확정
- 서버 라이선스 필요
- 초기 운영은 신청 승인 고객에게 한 달 무료체험 제공 후 월 9,900원 구독 전환
- 자동상세확정은 고객 Pro에 포함하지 않음
- 오더 확정 속도에 영향을 주는 결제/라이선스 네트워크 호출 금지

### CatchPro Navi Free

- 지도/주소 입력
- 기본 방문 확인
- 문의入口 역할

### CatchPro Navi Pro

- AWS 주소 동기화
- 방문순서/예상시간 계산
- 행정동 거리 확인
- 주소 편집

## 구현 시 주의사항

- 라이선스 서버 장애가 오더 확정 루프를 막으면 안 된다.
- Pro 권한 검사는 빠르고 캐시 가능해야 한다.
- APK 안에 결제 Secret, 네이버 Secret, 서버 관리자 키를 넣으면 안 된다.
- 홈페이지와 앱의 문구는 "공식 인성 연동"으로 오해되지 않게 작성한다.
- Play Store에 올라가는 Navi 앱에서는 외부 결제를 직접 유도하지 않는다.

## 완료 기준

내일 작업의 1차 완료 기준:

- 신청 페이지 초안이 있다.
- 라이선스 체크 API가 동작한다.
- 테스트 사용자 1명을 `trial` 또는 `active`로 등록할 수 있다.
- 인성 CatchPro Pro가 라이선스 활성 상태에서만 Pro 기능을 열 수 있다.
- 라이선스 체크가 오더 확정 속도에 영향을 주지 않는 위치에서 실행된다.
- 운영 문서에 신청, 결제 확인, APK 제공, 만료 처리 절차가 적혀 있다.
