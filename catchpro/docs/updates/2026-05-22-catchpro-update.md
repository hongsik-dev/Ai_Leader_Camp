# CatchPro 2026-05-22 업데이트 정리

## 업데이트 목표

오늘 업데이트의 핵심 목표는 휴대폰 2대 운영 구조에 맞춰 CatchPro를 역할별로 분리하는 것입니다.

- 인성데이터폰은 오더 리스트 진입과 확정 속도를 최우선으로 유지한다.
- 지도네비폰은 운행 중 현재 위치와 동기화된 주소를 크게 보여주고, 네이버/TMAP 내비 실행에 집중한다.
- 무거운 지도 SDK가 인성데이터폰 APK에 포함되지 않게 분리해서 안정성과 반응성을 확보한다.

## 주요 변경 사항

### 1. 역할별 APK 분리

Gradle product flavor를 추가해 같은 코드베이스에서 두 가지 APK를 만들도록 변경했습니다.

| 빌드 | 앱 이름 | 용도 |
| --- | --- | --- |
| `insungDebug` | CatchPro | 인성데이터폰용. 접근성 서비스와 자동상세확정/자동확정 중심 |
| `naviDebug` | CatchPro Navi | 지도네비폰용. 전체화면 지도와 네이버/TMAP 내비 중심 |

두 APK 모두 패키지명은 `com.catchpro.app`을 유지했습니다. 네이버 지도 Dynamic Map의 Android 패키지 인증이 기존 `com.catchpro.app` 기준으로 되어 있기 때문입니다. 따라서 두 APK는 같은 휴대폰에 동시에 설치하는 방식이 아니라, 서로 다른 휴대폰에 역할별로 설치하는 운영을 전제로 합니다.

### 2. 인성폰 APK에서 네이버 지도 SDK 제거

기존에는 인성폰 APK에도 네이버 지도 SDK가 포함되어 APK가 무겁고 지도 초기화 가능성이 남아 있었습니다. 오늘 변경으로 네이버 지도 SDK는 `naviImplementation`에만 포함됩니다.

```kotlin
dependencies {
    implementation("com.squareup.okhttp3:okhttp:4.12.0")
    add("naviImplementation", "com.naver.maps:map-sdk:3.23.2")
}
```

인성폰 변형에는 네이버 지도 대신 경량 대체 화면을 넣어 컴파일은 유지하되 지도 SDK와 네이티브 라이브러리는 포함하지 않습니다.

검증 결과:

- `insungDebug` APK에는 `libnavermap.so`와 `navermap-sdk` 리소스가 포함되지 않음
- `naviDebug` APK에는 네이버 지도 SDK 리소스가 포함됨

### 3. 지도네비폰 전체화면 지도 모드

`CatchPro Navi`는 앱 실행 시 바로 TMAP 연결 화면으로 진입하고, 하단 탭 내비게이션을 숨깁니다. 지도네비폰에서는 화면 전체를 지도 중심으로 사용합니다.

주요 동작:

1. AWS 주소 동기화로 주소 1~6 수신
2. 네이버 지도에 현재 위치와 주소 마커 표시
3. 방문 순서와 예상 거리/시간 표시
4. 주소 마커 또는 하단 목록 선택
5. 네이버 내비 또는 TMAP 실행
6. 방문 완료 시 해당 주소 슬롯 삭제

### 4. 주소 방문 완료 처리

지도네비폰 또는 TMAP 연결 탭에서 주소 방문이 끝나면 `완료` 버튼으로 해당 주소를 삭제할 수 있게 했습니다.

완료 처리 결과:

- 해당 주소 입력칸 초기화
- 네이버 지도 마커 제거
- 방문 순서 목록에서 제거
- AWS 주소 동기화 값도 갱신

이 기능은 여러 오더를 순서대로 수행할 때 이미 방문한 주소를 지워 새 주소를 받을 수 있게 하기 위한 것입니다.

### 5. 네이버 지도 안정성 개선

지도 객체와 마커를 매번 새로 만들지 않도록 개선했습니다. 기존에는 주소나 위치가 갱신될 때 지도 오버레이를 전체 재생성할 가능성이 있었고, 네비폰에서 지도 반응이 끊길 수 있었습니다.

개선 내용:

- `getMapAsync`는 최초 1회만 호출
- 마커와 경로는 key 기준으로 재사용
- 사라진 주소의 마커만 제거
- 남아 있는 주소의 마커는 위치/제목만 갱신
- 전체화면 지도 상단/하단 패널에 시스템 바 패딩 적용

### 6. 네이버 내비 딥링크 보정

네이버 지도 앱 호출 시 `appname`을 고정 문자열로 보내던 부분을 현재 앱 패키지명 기준으로 변경했습니다.

```kotlin
.appendQueryParameter("appname", context.packageName)
```

이렇게 하면 앱 변형이 바뀌어도 네이버 지도 호출 파라미터가 실제 설치된 앱 기준으로 맞춰집니다.

### 7. 설정탭 정리

설정탭에서 현재 운영 구조에 필요성이 낮아진 `실제 주행거리 계산` 카드를 숨겼습니다. 주행거리와 예상시간은 지도네비폰의 네이버 지도/길찾기 화면에서 다루고, 인성폰은 오더확정 속도와 안정성에 집중하는 구조로 정리했습니다.

## 테스트 결과

아래 빌드를 모두 성공 확인했습니다.

```powershell
.\gradlew.bat assembleInsungDebug assembleNaviDebug
```

추가 확인:

- 인성폰 APK 실행 확인
- 지도네비폰 APK 설치 확인
- `CatchPro Navi 0.1.11-navi` 실행 확인
- 실행 직후 크래시 로그 없음
- 네이버 지도 SDK 포함 여부가 flavor별로 분리된 것 확인

## 운영 기준

앞으로의 운영 기준은 다음과 같습니다.

- 인성데이터폰: 오더 리스트, 자동상세확정, 자동확정, 접근성 자동화 중심
- 지도네비폰: AWS 주소 수신, 전체화면 지도, 방문 순서, 네이버/TMAP 내비 실행 중심
- 인성폰에 지도 SDK나 무거운 지도 UI를 다시 넣지 않는다.
- 지도네비폰 기능은 오더확정 루프와 분리해서 개발한다.

이번 업데이트는 “오더를 더 빠르게 잡는 기본 기능”과 “잡은 오더를 더 효율적으로 배송하는 지도 기능”을 서로 방해하지 않게 분리한 작업입니다.
